# JudgeBox Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 实现可直接启动的 Windows 本地判题与对拍界面。
**Architecture:** C++ 执行器、生成器、判题引擎与异步本机 HTTP 服务，静态浏览器界面。
**Tech Stack:** C++20 / Win32 / Winsock / nlohmann/json / HTML CSS JS。
**Spec:** docs/superpowers/specs/2026-10-21-judgebox-design.md

## Global Constraints

Windows；不经 system/shell 运行提交；限制并回收进程树；时间 ms、内存 bytes；不宣称安全沙箱；保存用户原有执行器到 docs/process_win32.before.cpp.txt；不自动提交用户工作区。

## Review Focus

- 大输入和 stdout/stderr 同时大量写入：进程测试覆盖管道死锁。
- 缺失编译器、参考程序错误和生成器错误：端到端测试必须区分用户程序结果。
- 中文空格路径、参数末尾反斜线：执行器启动测试。
- 图边数非法、变量表达式过大、空字符集：生成器单测拒绝。
- 取消编译/运行、浏览器恶意跨域请求：API 测试与端口会话校验。

## Execution ledger

- 已核对现有代码：stdin 使用 NUL，管道未读取、未设置 STARTF_USESTDHANDLES；memoryLimit 未生效。现有未提交修改已备份。

- 执行器先以原实现运行 stdin/stdout 测试失败，再实现并通过；core 测试先因缺失接口失败；API 测试先因旧程序不是 HTTP 服务失败。
- Windows 编译器窄字符参数在中文路径失效：改用相对编译参数，Java class 复制到独立运行目录，仓颉使用短工作路径且显式提示不支持的配置。
- Ruling: 用户要求直接完成本地应用，沿用当前工作区，不增加设计审批或迁移工作树；保留原进程实现快照，不自动提交。
- 独立只读审查提出生成器工作量、工具链 PATH、Java 固定堆、草稿退出保存四项问题，均修复并追加/运行回归验证。复审未发现剩余阻断项。
- 生成器空重复回归在旧实现中长时间不返回，停止该测试后加入重复次数预算；LLONG_MIN 与候选边预算一并验证。
- Release 实际构建；ctest 的 process/core/api 三组通过。API 含 10 个测试方法及多个子用例，清除 MSYS2/仓颉 PATH 仍可编译运行。
- 真实 Chrome 无头 UI 测试通过：手动 AC/WA、生成 RUN、对拍反例、下载、工作区导入、草稿恢复、对话框、390px 页面无横向溢出；页面未出现 JavaScript 异常。
- 本机已验证 g++ 16.1.0、Python 3.11、Java 21、cjc 1.2.0；CYaRon 为可选脚本依赖，未宣称已经安装。
